## 独立待办：Dify 私有部署日志与错误排查

### 背景与目标

本地 Dify 页面操作曾出现 `Expecting property name enclosed in double quotes: line 5156 column 5 (char 576206)`，随后无法复现。检查时页面已无错误，API、Worker、plugin_daemon 近三小时日志未找到对应记录，根因尚未确定。该问题暴露了偶发错误发生后缺少现场证据的排障需求。

将日志与错误排查建设作为独立于 RAG 效果验证的部署任务：使页面异常、接口失败及异步入库失败可追溯到具体请求、任务、处理阶段和原因。它与知识库效果评测分别验收。

### 待调研与讨论

- 核查当前 Dify 版本自带的日志、异常采集配置及关联 ID，明确哪些能力可直接配置，哪些确需修改源码和重新构建镜像。
- 前端如何采集 JS 异常、Promise rejection、接口和响应解析错误，以及操作上下文、发布版本与 Source Map。
- 后端如何覆盖 Nginx、API、Worker、plugin_daemon、模型及数据库依赖，并关联前端请求、异步任务与插件调用；不能仅凭 HTTP 请求成功判断入库成功。
- 确定日志保留、集中检索、告警、访问权限与敏感信息脱敏要求。
- 评估工具、内网部署方式和维护成本。Sentry、Grafana Alloy、Loki 仅为讨论候选，不代表已选型；是否需要修改 Dify 源码尚待核查。

### 推进时点与验收方向

- 当前流程验证阶段：优先确认基础日志与异常堆栈可查，保留错误时间、操作步骤和运行版本。

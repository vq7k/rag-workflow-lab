## 5. 环节三：向量化、索引与召回评测

**输入**：固定分段及带目标来源的有答案题，另有无答案观察题。

**操作**：先真实调用 Embedding 检查模型、维度、输出数、有限值与耗时；再在 Dify 核查索引及分段身份。比较向量和混合检索时每轮只改变检索因素；保存 Top K 的分段身份、正文、分数和预期排名。

PyCharm 可直接运行 `scripts/demo_vector_search.py` 理解单题链路；批量真实验证入口为 `scripts/check_embeddings.py`。Dify 召回入口：

```shell
.venv/bin/python scripts/evaluate_dify_retrieval.py --method hybrid --semantic-weight 0.7
```

**指标**：Hit@1／Hit@3 判断目标答案分段是否进入前 1／3；MRR@3 反映目标首次出现的排名。无答案题不计入命中率分母，另观察候选是否足以回答。检索分数不是正确概率，不能直接拿分数决定答案质量或跨策略比较。

**产物与证据**：[向量化原理与指标](向量检索演示原理.md)、[召回测试及权重调优](召回测试记录.md)、[真实混合召回结果](../../runs/dify-retrieval-20261015-173222-555849/summary.json)。原有 drawio 源图见[项目环节](../diagrams/bge-m3-project-flow.drawio)、[时序](../diagrams/bge-m3-sequence.drawio)、[余弦计算](../diagrams/bge-m3-cosine.drawio)。

**完成条件**：模型真实调用、索引可查、目标来源身份正确。现有混合召回的三个有答案题 Hit@1、Hit@3、MRR@3 均为 1；只有三个开发问题，不能代表大规模知识库。召回通过仍不证明生成回答正确。

### 12.1 模型与调用路径迁移

**实验环境**：本机 Dify → Ollama，Embedding 为 bge-m3，生成为 qwen38-ms-8bit。其他环境应按实际可用模型、部署要求和实测效果选型，不要求复用这一组合。

**迁移原则**：模型服务可为本地运行时、统一网关或其他已批准的服务。先核实目标服务的模型版本、权限和接口兼容性；调用路径不是固定要求，不在公开仓库记录非公开地址、凭据或平台资源现状。

**部署前准入步骤**：

1. 获取目标服务实际可用的 Embedding 与生成模型，确认模型版本、中文检索表现、输入限制、向量维度与归一化规则、批处理限制、超时及调用权限。分别验证 Embedding 接口与聊天接口，不能仅凭聊天调用成功认定向量接口可用。
2. 在固定业务开发集上比较可用 Embedding 候选的召回和端到端回答，再冻结选定模型；模型名称或部署方式本身不能替代效果验证。
3. 记录 Provider、精确模型标识／版本、输入预处理、分块、维度及检索参数。更换 Embedding 模型或改变向量生成规则时，重新生成全部文档向量并建立新索引；即使维度相同，也不能混用不同模型的文档向量与问题向量。仅更换调用路径时，先核对实际模型与输入处理，并用固定样本验证输出一致性；无法确认兼容时按新的向量空间重建。
4. 保持资料与题集固定，重新测召回、生成、拒答、多轮及延迟／失败率；生成模型单独变更也要重测生成基线。旧本机成绩保留为历史，不沿用为服务器成绩，检索权重和阈值重新验证。
5. 在服务器执行真实调用与发布页检查，保留配置、输出和失败样本后，才更新目标环境的验收状态。当前上述步骤均为迁移要求，尚未执行。

### 12.2 正式验收的测试方案

业务通过率目标需在独立验收集上衡量，并预先定义统计口径和所需精度。本轮五个用例、六个轮次只验证开发流程，不支持正式业务准出。批量评测可采用“人工建立标准与校准集 → 模型批量评判 → 人工抽检／裁决”的方式，测试集、统计口径、校准与置信区间要求见[生成评测 SOP 第 10 节](生成回答评测规则.md#10-正式验收测试方案批量评测与自动评判)。自动评判是后续待开发能力，不属于本轮交付。

# 03 向量化与召回评测

输入：固定资料与分段、有答案题的目标来源、无答案观察题。

输出：Embedding 契约、索引版本、逐题召回与检索基线。

## 操作

1. 真实调用 Embedding 服务，记录 Provider、模型精确版本、输入预处理、向量维度和归一化方式；核查返回数量、有限值与错误处理。
2. 确认文档和问题使用同一向量空间。记录生成耗时、输入量、批处理大小与失败；仅端口可达不能证明模型推理有效。
3. 在知识库核查目标文档、分段身份和索引状态，冻结资料与题集版本。分段编号不是跨文档唯一身份，标注时同时保存文档和分段信息。
4. 固定 Top K，先测基线策略。比较向量、关键词、混合或重排时，每轮只改变一个因素，记录实际执行配置。
5. 保存每题请求、返回候选的身份、正文、分数、排名、耗时和失败；检查标注依据是否进入实际候选，不只看页面分数。
6. 对有答案题计算 Hit@K 与 MRR@K；无答案题单列观察。报告适用题数、失败数和数据范围，不将小样本成绩外推到完整业务。
7. 调权重或阈值时，在固定开发集循环测试；在未参与调参的题集上确认效果，不能根据单题分数设全局阈值。

## 指标解释

- Hit@K：应答题的目标依据是否出现在前 K 个候选中。
- MRR@K：目标首次命中的排名倒数的平均值；前 K 未命中记 0。
- 调用失败率和客户端耗时：与召回质量分别报告，失败不静默剔除。
- 分数反映当前策略的相关程度，不是答案正确概率；不同检索策略的分数不直接横向比较。

## 仓库本机入口

从项目根目录执行，先按[脚本说明](../../scripts/README.md)配置环境：

```shell
.venv/bin/python scripts/check_embeddings.py
.venv/bin/python scripts/evaluate_dify_retrieval.py --method vector
.venv/bin/python scripts/evaluate_dify_retrieval.py --method hybrid
```

这些是本机、固定示例语料的复现入口。Embedding 验证有指定模型与维度契约，召回脚本固定题集和分段校验；不支持直接连接远程服务或任意替换题集。

## 变更与完成条件

更换 Embedding 模型或向量生成规则时，重新生成文档向量并建立新索引；相同维度不代表空间兼容。仅换调用路径时先核对模型与预处理，并用固定输入验证兼容，无法确认时按新空间重建。迁移后重测召回与端到端基线。

完成须有真实模型输出、可用索引、可定位来源和逐题结果。召回通过不代表回答正确，继续[应用配置与问答](04-应用配置与问答.md)。

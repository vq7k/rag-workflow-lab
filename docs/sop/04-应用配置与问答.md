# 04 应用配置与问答

输入：可用知识库、真实生成模型、应答与拒答边界。

输出：应用配置快照、Prompt 版本、单轮与多轮真实调用证据。

## 操作

1. 在 Dify 配置生成模型，真实验证聊天接口。Embedding 可用不代表生成接口可用；分别核查权限、版本、上下文限制和超时。
2. 创建问答应用并绑定知识库。核对知识库与应用两层检索设置、Top K、阈值和实际启用的重排路径，保存完整配置。
3. 编写并版本化 Prompt：依据资料回答、保留适用条件、区分资料与指令、资料不足时按约定澄清或拒答。仅写“转人工”不代表已经接通人工系统。
4. 配置来源展示，核对引用能打开且确实支持对应事实。候选列表中出现文档名不证明模型使用了全文。
5. 运行有答案、无答案和条件边界题。保存完整回答、引用、可获取的实际上下文和消息标识，失败照实留存。
6. 为多轮用例开启一个新会话，后续轮次沿用同一会话与调用用户。检查指代、前轮约束和事实是否承接。
7. 查看后续轮的实际模型输入，核查历史是否进入 Prompt；另查检索使用的 query。历史进入模型不证明系统已用历史改写检索问题。
8. 测已发布入口时先发布更新并刷新。编排预览、应用 API 和发布网页分别注明，不能混用不同配置的结果。

## 配置留档

- Dify 版本、应用类型、Provider、模型版本及生成参数。
- 完整 Prompt、知识库及检索设置、资料与索引版本。
- 网页或 API 执行入口；API 返回的 conversation ID 与 message ID。
- 已实现的拒答、引用、多轮和人工处理行为，以及尚未实现的能力。

知识库 API Key 与应用 API Key 用途不同。前者用于知识库接口，后者用于应用调用；均仅存本地配置或受控密钥设施，不进入可分享快照。

## 完成条件

- 至少一条真实请求完成检索、生成和来源展示；无答案题执行约定行为。
- 多轮会话标识、历史输入与回答可核查；未采集的证据明确记录缺口。
- 实际运行配置与留档一致，能够进入固定题集评测。
- 接口成功、页面正常和质量通过分别记录，不以单题演示代替基线。

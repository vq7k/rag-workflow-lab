# 05 生成评测

输入：固定题集、资料版本、实际发布配置及完整回答。

输出：可复核的逐轮标注、质量基线、失败样本与问题清单。

## 执行与标注

1. 使用[题集模板](../../templates/test-cases.json)固定问题、预期行为、必答要点、适用条件、来源和禁止结论。单轮独立成题，多轮按组保存每轮预期。
2. 运行前核对已发布配置，保存模型与版本、完整 Prompt、生成参数、资料、检索配置及题集版本。配置文件不含凭据。
3. 每次新建运行目录，真实调用应用。单轮使用新会话，多轮续传返回的会话 ID；保存请求、完整响应、用量、耗时与消息身份。
4. 调用失败或超时保留原结果。重试单独计次；多轮链路失败时不要把后续轮当作正常独立请求继续评分。
5. 对照实际检索上下文、来源原文和标准要点逐轮标注。可参考[标注表模板](../../templates/review.csv)，实际采集脚本会自动创建待标注表。
6. 逐项判定核心正确、资料支持、条件保留、拒答与多轮衔接。使用 `pass/fail/pending/na`；整体 `overall` 使用 `pass/fail/pending`。理由引用错误原句或支持证据，并记录标注者。
7. 汇总调用成功、失败、跳过和各维度结果。`pending` 不计通过，不适用项不混入该维度分母；报告未裁决与失败的数量。
8. 根据证据将问题分到资料、检索、生成、会话接入或体验环节，写下一步验证动作，不凭现象直接认定根因。

缺少完整上下文时，资料支持保留待核查；引用候选不能替代实际输入证据。回答主动增加的结论也必须有依据并保留适用条件。

## 仓库本机执行入口

先准备本地 `.env` 中的应用 Key，并核对脱敏配置快照。从项目根目录执行：

```shell
.venv/bin/python scripts/evaluate_dify_generation.py --label baseline-v1
.venv/bin/python scripts/summarize_generation.py runs/实际运行目录
```

如需附配置快照，在采集命令增加 `--snapshot 相对路径/config.json`，仍须人工核对其与实际配置一致。脚本只访问本机 Dify，使用固定示例题集；没有通用题集导入参数。新语料先适配题集入口和契约，再执行，不直接把模板当作可运行输入。

采集保存真实回答，汇总只计算人工标签；两者都不自动判断语义。客户端 blocking 耗时不是首 Token 或纯模型耗时。

## 批量评测与自动评判

自动语义评判尚未实现。需要扩大评测时，按以下顺序引入模型评判或评测平台：

1. 分离开发集、评判器校准集和独立验收集，业务确认标准答案；规模按覆盖与统计精度确定。
2. 从不同错误类型分层建立人工金标，交叉裁决争议；保留一部分样本验证评判器，不参与调评判 Prompt。
3. 固定真实评判模型、Prompt 和结构化输出，输入问题、历史、标准、来源、实际上下文及完整回答，保留原始输出。
4. 对照人工报告逐维一致性、混淆矩阵，特别检查自动判通过而人工判失败的比例；未达到事先约定门槛，不用于准出。
5. 批量评判后，人工分层抽查通过与失败项，高风险、异常和争议全部裁决。评判超时或非法输出记错误／待核查，不能算通过。
6. 报告题数、通过数、分组结果与置信区间；多轮相关轮次不当作独立样本扩充题数。更换评判模型或规则后重新校准。

## 完成条件

结果能逐题追溯到原始回答、实际配置和判断依据；调用契约测试通过与真实质量通过分开报告。只有真实输出与标注齐全才能建立基线；正式质量准出还需独立验收集与约定门槛。

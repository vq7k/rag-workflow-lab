# 07 发布与恢复

输入：选定配置、真实基线、回归决定、依赖和已知限制。

输出：版本包、恢复证据、发布网页验收和发布记录。

## 版本留档

1. 复制[发布记录模板](../../templates/release-record.md)，填写发布范围、版本、模型、资料和索引、题集、Prompt、检索配置与验收结论。
2. 从 Dify 导出官方 DSL，检查文本和导出选项，移除凭据及非公开信息；保存哈希和 Dify／DSL 版本。
3. 另存可分享配置快照、依赖清单、真实评测入口和已知失败。明确发布为开发测试、有限试用或正式版本。
4. 说明恢复所需的知识库、模型、插件、凭据与数据库状态；DSL 主要是应用配置，不能作为这些依赖的完整备份。

## 恢复验证

1. 在独立副本或隔离环境导入，不覆盖正在使用的应用。
2. 核对模型参数、Prompt、检索设置和插件依赖；按目标环境重新绑定知识库与受控凭据。
3. 用新会话执行关键真实问答，保存消息 ID、完整回答和来源，确认恢复后的实际配置。
4. 记录验证环境和边界。同工作空间复用既有依赖的导入成功，不能证明跨服务器灾备成功。
5. 如创建临时凭据，用完撤销并核查撤销状态；不能把临时 Key 写入版本包。

## 发布验收

1. 核对选定版本，执行发布更新并刷新最终入口。
2. 在实际网页检查有答案、无答案和连续追问；单轮独立会话，多轮沿用同一会话。
3. 保存本轮新消息，关联实际配置、回答、引用、错误和耗时；不复用旧消息作为本次发布证据。
4. 经人工确认文本、引用、长回答和多轮交互正常。截图已采集时登记文件；未采集时如实注明，不能虚构页面证据。
5. 分别记录接口、核心功能、严格质量和恢复状态。未达到质量门槛时限制使用范围，不能将开发演示标为正式准出。

## 回退准备

保留上一版完整配置与依赖，写明触发条件、执行者、恢复步骤和关键真实复测。发布后发现关键退化时按记录恢复，核对实际生效版本并更新发布结论。

## 完成条件

- 版本、配置、依赖、评测与实际入口可关联。
- 完成独立恢复验证和发布页人工检查，边界明确。
- 回退步骤可执行，质量失败与遗留问题保留。

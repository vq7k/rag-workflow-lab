# 历史消息与生成人工复核

2026-10-16 从本机 Dify 数据库只读补采六条已知问题的历史消息。每个问题恰好匹配一条记录，没有重新调用模型。仅选择消息、输入输出、会话身份和用量等必要字段，没有导出账号、凭据或整库备份。

- `*-stored-message.json`：Dify 保存的有序模型消息、最终回答、检索候选元数据、Token 与关联身份。`created_at_utc` 为数据库 UTC 时间。
- `results.json`：历史请求关联；`review.csv`：逐轮人工判断，标注者为 Codex 对照复核，没有运行评分 LLM。
- `summary.json`：人工计数；六轮中两轮整体通过、四轮存在条件或资料支持问题。历史入口混合，不是统一 API 基线、独立准确率或正式验收成绩。

## 关键复核结果

| 样本 | 实际保存的上下文 | 判断变化 |
|---|---|---|
| S01 | 有定义及实现比较 | 两个核心事实可直接支持，整体通过 |
| S02 | 操作、实现、栈定义；没有扩容例外 | 模型沿用 O(1) 简写；优先关注输入条件不自足，不能称模型忽略已给例外 |
| S03 | 包含完整实现比较、节点复用例外、基本类型范围 | 回答在有条件输入下遗漏限定，并补充未给出的分配／复制细节 |
| S04 | 栈相关候选与完整拒答 Prompt，无快速排序方法 | 明确拒答，符合本题预期 |
| M01 第一轮 | 定义及实现，没有扩容例外 | 核心定义正确，主动复杂度扩展缺限定 |
| M01 第二轮 | 包含前一轮 USER、ASSISTANT 与当前问题；操作和实现无扩容例外 | 简单指代连续成功；复杂度仍缺限定 |

这些是 Dify 保存的完整消息序列，可用于核对实际组装输入；不是 Ollama 原始 HTTP 参数、插件传输记录或分布式 Trace。模型名与用量来自历史记录，精确参数以另存配置快照和历史配置记录为依据，不据此补造历史 Provider 请求。
